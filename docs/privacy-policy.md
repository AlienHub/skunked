# SKUNKED 隐私与数据处理说明

生效日期：2026-03-07

## 1. 设计原则

SKUNKED 遵循“最小化上报”和“本地优先”原则：

- 本地先做白名单、黑名单和启发式检测。
- 仅在需要云判定时发送最小必要字段。
- 默认不上传页面正文、完整 DOM 和用户输入内容。

## 2. 上报字段

默认上报字段包含：

- 事件类型（阻断、告警、继续访问、误报反馈）；
- 域名（`urlHost`）；
- 判定层级、动作、置信度；
- 匿名安装 ID；
- 组织 ID（企业激活后）；
- 标题与 H1 摘要（截断后，便于复盘）。

## 3. 不采集内容

默认不采集：

- 完整页面 HTML；
- Cookie、账号密码、表单值；
- 浏览器历史记录全文；
- 与风险判定无关的个人内容。

## 4. 数据用途

上报数据仅用于：

1. 统计阻断和告警效果；
2. 复盘误报与漏报；
3. 生成企业安全事件导出报表；
4. 优化风险策略与规则。

## 5. 数据保留与导出

- 云端事件可按组织和时间窗导出（CSV/JSON）。
- 建议企业根据内部制度配置保留周期。
- 企业可以将导出结果对接到现有管理系统或 SIEM。

## 6. 公开数据集说明

- SKUNKED Open Data 是独立公共数据集与只读服务；
- 公开数据集仅发布应用官网域名与人工确认钓鱼域名（host 级别）；
- 不公开用户访问 URL 路径、页面正文、账号信息或组织私有日志；
- 新增公开域名需经过人工审核流程后发布。

## 7. 员工告知建议

企业上线时建议同步公告：

- 插件用于识别钓鱼风险，不读取员工私密业务内容；
- 插件会记录与风险相关的最小元数据；
- 误报可通过插件反馈机制提交。
